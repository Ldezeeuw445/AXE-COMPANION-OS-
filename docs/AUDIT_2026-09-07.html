Critical blockers
01 — Blockers
CRIT-1

The public anon key reads and writes AXE's memory

public.memory carries one policy: FOR ALL TO PUBLIC USING (true) WITH CHECK (true). TO PUBLIC includes anon, and the anon key ships in every browser bundle of all three apps. Confirmed against production with nothing but that key:

GET /rest/v1/memory?select=*&limit=1 206 content-range: 0-0/17223 [{"id":"10facedd-…","agent":"axe_trader","user_id":"acff7a12-…

global_memory (18,281 rows) is one step behind: SELECT and UPDATE granted on auth.role() = 'authenticated' with no user_id predicate.

CRIT-2

Every background job has been dead since July

Production runs on a VPS, not Vercel — so the eight cron jobs in vercel.json have never fired on this host. The Feed is the app's front door and its last row landed on 6 July.

$ curl -I https://www.axecompanion.com/ server: nginx/1.24.0 (Ubuntu) ← Vercel serves "server: Vercel"
CRIT-3

The demo endpoint gives the product away

POST /api/auth/demo signs in an anonymous user, then writes plan: "founder", founder_badge: true, chat_quota_exempt: true — no rate limit, unlimited repeats. Production already holds the result:

plan=founder n=118 founder_badge=117 chat_quota_exempt=118 paid subscriptions = 0

05 — Everything else worth fixing

24 tables have RLS on and zero policies

critical

All 15 intel_* tables plus axe_convictions, core_webhook_secrets and shared_memory. The app cannot read them at all — Intel renders empty by construction, not by accident.

Migration history has permanently diverged

warning

47 Companion migrations sit in the repo. The live history holds 38 entries and every one is an AXE Core migration. Companion's schema was applied by hand, so supabase db push would now replay all 47 from scratch.

Deployed Edge code is not this repo's code

warning

intel-proxy was deployed from /Volumes/EagetSSD/TRADING-OS/…, livekit-token and ai-proxy from an AXE-CORE path. One Supabase project backs all three apps with no ownership boundary.

Core features have never been used in production

warning

135 users, 290 chat messages — and watchlists, alerts, positions, vault_items, user_journal_entries, mt5_positions are all at zero rows. The RAG corpus is 27 chunks, which does not make “personal AI with RAG per user” true yet.

Build passes, lint does not

cleanup

tsc --noEmit and next build are clean, so ignoreBuildErrors: true is now pure downside. 27 lint errors remain, six of them from AXE ADAPTIVENESS/ — one of four scratch directories committed at the repo root.

Next 16 deprecations

cleanup

The middleware convention is deprecated in favour of proxy, and instrumentation.ts:39 calls process.pid in the Edge runtime. robots.txt and sitemap.xml both 404.

06 — The order to fix it in
Phase 1Hours · today
1
Close public.memory

Replace memory_service_all with an owner policy — USING (auth.uid()::text = user_id) plus a service-role bypass. Then rotate the anon key: assume all 17,223 rows are public.

2
Close global_memory

Add a user_id predicate to SELECT and UPDATE. Scope genuinely global reads to an allow-list, not auth.role() = 'authenticated'.

3

Grant free with the normal 20/day quota, or a time-boxed trial — never founder + chat_quota_exempt. Then downgrade the 118 existing rows.

Drop the public /migrations page and delete /api/internal/migrate — its own header says “DELETE after use”.
